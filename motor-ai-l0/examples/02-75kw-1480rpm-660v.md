## 5. 这个算例能说明什么

**效率并列时的二次排序。** 前 5 名的**展示值**全部为 96 —— 这是配置项 `efficiencyCap`（默认 96）的封顶结果，不是巧合。封顶的意义是与 L1 同口径，避免 L0/L1 两层排序跳变。

⚠️ **v0.2.4 起这两个数要分开读**：`efficiency` 是钳位后的展示值（触顶时都等于 96），
`efficiency_raw` 才是未封顶真值，**排序按 `efficiency_raw` 进行**，所以 Top5 的先后顺序是有物理依据的，
不是并列。要看真实差距请读结果行里的 `efficiency_raw` 字段。若仍只见并列，可换维度看：

| 维度 | 结论 |
|---|---|
| 总损耗 | #5（1867 W）最优，比 #2（2603 W）低 28% |
| 温升 | #4（26.5 K）最优 —— 6 极方案整体优于 4 极 |
| 轭磁密 | 4 极方案 1.60 T 已越过 1.5 T 警告线，6 极 1.38 T 更从容 |

> 实践建议：`sort_by` 用 `efficiency` 拿到第一梯队后，再用 `total_loss` / `temp_rise` 复排一次（`sort_by` 白名单：`efficiency` `torque_density` `temp_rise` `total_loss` `power`，后两者升序）。

## 6. 复现命令

```bash
node -e "
import('./tools/l0/param-matrix.mjs').then(async (M) => {
  const E = await import('./tools/l0/l0-estimate.mjs')
  const cfg = { l0Mode: 'auto', level: 'l0' }
  const rows = M.buildParamMatrix({ power_kw: 75, speed_rpm: 1480, voltage_v: 660, motor_type: 'induction', count: 120 }, cfg).matrix
  for (const by of ['efficiency', 'total_loss', 'temp_rise']) {
    const r = E.runL0Estimate({ params_list: rows, top_n: 3, sort_by: by }, cfg)
    console.log(by, '->', r.results.map(x => x.params.stator_od + '/' + x.params.poles + 'p'))
  }
})
"
```
