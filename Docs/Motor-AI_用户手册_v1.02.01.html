1. 系统概述

Motor-AI 是一套面向电机设计工程师的 AI 辅助设计系统，将自然语言需求解析、Motor-CAD 自动化批量求解、多智能体辩证评审、蒙特卡洛风险沙盘、数据飞轮进化五大能力集成于单一 Web 平台。

v1.02.01 的核心设计哲学是 "放大火花，举起镜子"——既用 AI 放大工程师的创意与直觉（放大轨），也用 AI 收敛团队的一厢情愿与盲点（收敛轨），双轨并行，在决策门交汇，强制工程师同时阅读"支持"与"反对"意见后方可决策。

设计理念
  • 本地优先：所有 AI 智能体运行于本地 Ollama Qwen2.5-3B，数据不出机
  • 严格脱敏：调用云端 API 时自动剥离几何尺寸、材料牌号、客户信息
  • 辩证制衡：放大轨与收敛轨并行，决策门强制双报告齐备
  • 越用越聪明：采纳/拒绝决策自动驱动技能模板进化与规则挖掘

核心能力一览

能力技术说明
需求解析本地 LLM + 正则自然语言 → 结构化电机规格 JSON，支持电机类型识别
批量求解Motor-CAD COM参数扫描矩阵自动求解，电磁分析+热分析+耦合分析
辩证评审LangGraph 双轨放大轨(评审推荐师) + 收敛轨(四剑客) 并行生成报告
沙盘推演蒙特卡洛引擎1000 次参数扰动，5 种失效模式分类，P5/P50/P95 输出
数据飞轮进化引擎采纳→技能模板生成+规则挖掘；拒绝→失败特征记录
报告生成本地/云端 LLMMarkdown 格式技术报告，含五维度方案说明
审计追溯SQLite 日志全流程操作可溯源，每个智能体每步操作有记录

3.3 安装步骤

  1. 克隆/复制项目：将 D:\MotorDesign 目录完整复制到目标机器
  2. 创建虚拟环境： 
    cd D:\MotorDesign
python -m venv venv
venv\Scripts\activate
  3. 安装 Python 依赖： 
    pip install flask langgraph langchain-ollama pywin32 numpy python-dotenv openai
  4. 安装 Ollama 并拉取模型： 
    # 安装 Ollama 后执行
ollama pull qwen2.5:3b-instruct-q4_K_M
  5. 配置环境变量：复制 .env.example 为 .env，按实际环境填写
  6. 放置 Motor-CAD 模板：将 .mot 文件放入 Templates/ 目录
  7. 启动系统：双击 start_ui.bat
启动成功标志：浏览器自动打开 http://127.0.0.1:5000，左侧侧边栏显示 12 个导航项，底部状态栏显示 "v1.02.01 | 2026-07-27"。

4. 系统配置

4.1 环境变量 (.env)

所有配置集中在项目根目录的 .env 文件中，使用 .env.example 作为模板：

# ---- 系统版本 ----
SYSTEM_NAME=Motor-AI
SYSTEM_VERSION=1.02.01
VERSION_DATE=2026-07-27 01:43

# ---- 本地模型 ----
OLLAMA_BASE_URL=http://127.0.0.1:11434
LOCAL_MODEL_NAME=qwen2.5:3b-instruct-q4_K_M
USE_GPU=true

# ---- 云端模型 (DeepSeek) ----
# 保持占位符则全本地运行，填入真实 Key 则启用云端增强
DEEPSEEK_API_KEY=sk-your-key-here
DEEPSEEK_BASE_URL=https://api.deepseek.com
CLOUD_MODEL_NAME=deepseek-chat

# ---- Motor-CAD ----
MOTORCAD_EXE_PATH=D:\Motor-CAD\11_1_5\Motor-CAD_11_1_5.exe
MOTORCAD_INSTALL_DIR=D:\Motor-CAD\11_1_5
MOTORCAD_PROGID=MotorCAD.AppAutomation
MOTORCAD_USE_MODE=auto
MOTORCAD_TEMPLATE_FILE=Templates.mot

4.2 关键配置说明

配置项可选值说明
MOTORCAD_USE_MODE auto / manual / simulation auto：尝试 COM 自动化，失败则降级模拟
manual：不调用 COM，导出参数 CSV → 手动 Motor-CAD 求解 → 导入结果
simulation：纯经验模型估算，不启动 Motor-CAD
DEEPSEEK_API_KEY 占位符 / 真实 Key 占位符 sk-your-key-here → 全本地零上云
真实 Key → 启用云端深度分析与报告润色（自动脱敏）
LOCAL_MODEL_NAME Ollama 模型名 4GB 显存推荐 qwen2.5:3b-instruct-q4_K_M (2.5GB)
USE_GPU true / false 7B 模型建议关闭（4GB 显存不足）
安全提示：.env 文件已加入 .gitignore，不会被提交到 Git 仓库。云端 API Key 仅存储在本地，系统在调用云端前会自动执行脱敏处理，剥离几何尺寸、材料牌号和客户信息。

4.3 界面配置入口

除 .env 文件外，也可通过 Web 界面的 系统设置 面板在线配置，修改后点击"保存设置"即可生效（写入 .env）。支持配置项包括：本地模型名称、GPU 加速开关、云端 API Key、云端模型名称、Motor-CAD 路径与使用模式。

5. 功能面板详解

系统左侧导航栏共 12 个功能面板，分为基础工作流（7 个）和高级分析（5 个）两组。

5.1 仪表盘 首页

系统启动后的默认页面，一览全局状态。

  • 四张状态卡片：
    • 本地 AI Ollama 运行状态与模型名称
    • 云端 AI DeepSeek API 连通性与模型
    • 数据库 已存储方案总数
    • Motor-CAD COM 连接状态
  • 快捷操作：新建需求解析、查看历史记录、系统设置
  • 工作流程图：四步流程导航（需求解析 → 批量求解 → 方案对比 → 生成报告）

5.2 需求解析

将客户的自然语言需求描述转化为结构化的电机规格参数。

操作步骤

  1. 在左侧文本框粘贴客户需求描述（邮件、文档内容等）
  2. 可点击底部示例标签快速加载测试用例（叉车/伺服/无人机/矿用/家电）
  3. 点击"AI 解析需求"按钮，本地 AI 自动提取参数
  4. 解析结果以表单形式显示在右侧，所有字段均可手动编辑修正
  5. 点击"下一步：批量求解"进入求解阶段

解析字段

字段类型说明
motor_type文本电机类型（默认"异步电动机"，支持永磁同步/无刷直流/开关磁阻）
power_kw数字额定功率 (kW)
voltage_v数字额定电压 (V)
speed_rpm数字/null额定转速 (rpm)
cooling文本冷却方式（自然风冷/水冷/油冷/未知）
efficiency_target数字/null效率目标 (%)
stator_od_limit数字/null定子外径限制 (mm)
application文本应用场景（叉车/无人机/电动汽车/工业泵/家电/通用）
解析引擎：系统使用三级解析策略——(1) 正则表达式快速提取数字与关键词；(2) 本地 Ollama Qwen2.5-3B 深度理解语义；(3) 云端 DeepSeek API 增强解析（需配置真实 Key）。三级自动降级，确保离线可用。

5.3 批量求解

根据解析的规格参数，生成参数扫描矩阵，调用 Motor-CAD 批量求解。

三种求解模式

模式耗时说明
COM 自动化~200s/组自动修改 .mot 参数 → 电磁分析 → 热分析 → 读取结果，全自动
半自动求解~30s/组自动修改参数并启动 Motor-CAD，用户手动点击"求解热模型"按钮，自动读取结果
手动导入—导出参数 CSV → 在 Motor-CAD GUI 手动求解 → 导入结果 CSV
纯模拟<1s/组经验模型估算，不启动 Motor-CAD，用于快速验证流程

参数矩阵

系统根据需求规格自动生成参数扫描矩阵，包含以下参数：

  • 核心参数：定子外径 (stator_od)、极数 (poles)、定子槽数 (slots_stator)、转子槽数 (slots_rotor)、线圈匝数 (turns_per_coil)
  • 结构参数 (v1.02.03 扩展)：
    • 定子内径 (stator_id) = OD × 0.58~0.65
    • 转子外径 (rotor_od) = 定子内径 − 2 × 气隙
    • 铁心长度 (core_length) = 60 + 功率 × 2.5
    • 气隙 (air_gap) = 0.5~1.0 mm
    • 齿宽 (tooth_width) = π × 内径 / (2 × 槽数)
    • 轭厚 (yoke_thickness)
    • 轴径 (shaft_dia)
  • 运行参数：电压 (voltage)、转速 (speed)
实时进度：求解过程中，进度条和日志区域实时显示每条方案的求解状态（如"求解进度: 3/10..."），COM 模式下还显示电磁分析/热分析的阶段进度。

5.4 方案对比

对批量求解结果进行排序、筛选、AI 点评和深度分析。

功能

  • Top-N 排序：按效率降序显示 Top 5/10/20 方案
  • 效率筛选：设置最低效率阈值过滤方案
  • 本地 AI 点评：Qwen2.5-3B 逐方案生成五维度评价（结构/电磁/热/损耗/总结）
  • 云端深度分析：DeepSeek API 生成专业对比报告（自动脱敏）
  • 方案反馈：对方案标记"采纳"或"拒绝"，驱动数据飞轮

对比表字段

分类字段
基本信息序号、求解模式、效率、温升、转矩、功率
结构参数定子外径、定子内径、转子外径、铁心长度、气隙、齿宽、轭厚、轴径
电磁参数极数、定子槽数、转子槽数、线圈匝数、齿磁密、气隙磁密、电密
损耗参数铜耗、铁耗、总损耗、功率因数
热参数发热因数、铜线温度、磁钢温度

5.5 报告中心

生成完整的电机设计方案技术报告，支持预览、下载和管理历史报告。

报告结构

  1. 需求概述：电机类型、功率、电压、转速、冷却方式、效率目标、应用场景
  2. 方案对比表：Markdown 表格，含结构/电磁/损耗/热参数四大类
  3. 方案设计说明：槽配合选择原则、参数设计思路
  4. 性能对比分析：效率、温升、磁密饱和度、损耗分布
  5. 推荐方案论证：从五维度详细论证最佳方案
  6. 风险提示：磁饱和风险、热风险、制造可行性
  7. 优化建议：下一步优化方向
  8. 脱敏声明：报告尾部自动附加"本报告基于真实仿真数据生成，部分设计细节已脱敏处理。"
报告生成引擎：(1) 本地模板报告（Ollama 未启动时）；(2) 本地 LLM 草稿 + 云端润色；(3) 云端直接生成。三级自动选择。

5.6 历史记录

查看所有历史求解结果，支持 CSV 导出备份。

  • 统计卡片：总方案数、最高效率、平均效率
  • 结果表格：全部求解记录，含结构参数、电磁参数、损耗、热参数等 33 个字段
  • CSV 导出：一键导出全部数据为 CSV 文件

5.7 系统设置

在线配置系统参数，修改后保存即写入 .env 文件。

  • 本地 AI 模型：模型名称（下拉选择/手动输入）、GPU 加速开关
  • 云端 AI：DeepSeek API Key、模型名称
  • Motor-CAD：EXE 路径、COM ProgID、使用模式（auto/manual/simulation）、连接状态检测

6. AI 团队 — 多智能体辩证工作流

AI 团队面板是系统的核心功能，一键启动 LangGraph 多智能体工作流，自动完成从需求解析到报告生成的全流程。

6.2 各节点职责

序号节点职责引擎
1需求分析师解析客户描述，提取电机规格 JSON（含电机类型）本地 LLM
2方案生成师生成参数矩阵，批量求解，存入数据库Motor-CAD COM
3a评审推荐师 放大生成支持报告，强化推荐理由本地 LLM / 云端可选
3b收敛阵营 收敛四剑客联合生成反对报告（详见第 7 节）本地 LLM
4决策门双报告齐备后解锁采纳/拒绝按钮UI 交互
5报告撰写员生成正式 Markdown 技术报告本地 LLM / 云端可选

6.3 操作步骤

  1. 在"客户需求描述"文本框输入需求文字
  2. 选择方案数量（2/10/30/50 组）
  3. 可选：勾选"云端评审"和"云端报告"启用云端增强
  4. 点击"启动 AI 团队"按钮
  5. 观察流水线各节点状态变化（等待中 → 运行中 → 完成）
  6. 底部实时日志栏显示详细运行进度

12.4 ActiveX 注册模式

  • 多客户端 (id=93)：多实例并发
  • 单客户端 (id=94)：推荐 COM 可用
  • 免注册 (id=95)：禁用 COM 不可用

COM 线程限制：Motor-CAD COM 使用 STA (Single-Threaded Apartment) 模型，所有 COM 调用必须在调用 CoInitialize() 的同一线程内执行。系统在 connect() 时初始化 COM，后续调用在同一工作线程内完成。

14. 常见问题与故障排除

Q1: 启动后界面显示"Ollama 未启动"

原因：Ollama 服务未运行或模型未拉取。

解决：

  1. 打开终端执行 ollama serve 启动服务
  2. 执行 ollama pull qwen2.5:3b-instruct-q4_K_M 拉取模型
  3. 确认 http://127.0.0.1:11434/api/tags 可访问
  4. 刷新浏览器页面

Q2: Motor-CAD COM 连接失败

原因：ActiveX 注册模式为"免注册"，或 Motor-CAD 未安装/未授权。

解决：

  1. 打开 Motor-CAD → 菜单"默认设置 → 控件注册" → 选择"单客户端设置"
  2. 或运行 python Scripts/com_diagnose.py 执行 7 步诊断
  3. 确认 Motor-CAD 为正式授权版本（非 Demo）
  4. 如仍失败，将使用模式改为 manual 或 simulation

Q3: COM 连接超时（约 60 秒后失败）

原因：Motor-CAD v11.1.5 需 80-120 秒启动，但 Dispatch 内部超时仅 60 秒。

解决：系统已内置预启动模式——先手动启动 Motor-CAD exe，等待 90 秒完全加载后再 Dispatch 连接已运行实例。通常从零启动约 82 秒可连接成功。

Q4: AI 团队工作流卡住，决策门一直"等待中"

原因：LangGraph 并行节点写入冲突（InvalidUpdateError）或前端未检查 HTTP 状态码。

解决：v1.02.02 已修复——并行节点返回值不再包含 step/status 字段，errors 改为 Annotated[List[str], operator.add] 允许并行追加。如仍出现，检查 Ollama 是否正常运行。

Q5: 评审报告中出现"虚构"字样

原因：云端 AI 对脱敏数据产生"自我免责"理解，声明为"虚构报告"。

解决：v1.02.04 已修复——所有云端提示词重写，明确告知 AI "收到的脱敏数据来自真实电磁仿真，严禁使用虚构/假设/模拟数据等字样"。报告尾部自动附加脱敏声明。

Q6: 正式报告中出现"极数: 不详"

原因：poles 字段仅存在于嵌套的 params 字典中，但报告代码直接用 r.get('poles') 取值。

解决：v1.02.04 已修复——_run_simulated 和 _run_motorcad_with_instance 返回值新增 poles、voltage、speed 字段。

Q7: GetVariable 无限挂起

原因：某些变量名（如 OperatingSpeed、MaxTemperature）会导致 COM 调用无限等待。

解决：系统采用白名单机制，仅查询已验证的变量名。返回 code=-2 表示变量不存在（不挂起）。

Q8: 修改代码后界面无变化

原因：Flask 默认不热重载。

解决：修改 Python 代码后必须重启 Web UI——关闭 start_ui.bat 窗口，重新双击启动。

Q9: GPU 显存不足 (4GB)

解决：使用 qwen2.5:3b-instruct-q4_K_M (2.5GB 显存) 而非 7B 模型。在系统设置中关闭 GPU 加速改用 CPU 推理（较慢但稳定）。未来内存升级到 32GB 后可升级至 7B 模型。

Q10: 数据库迁移

说明：系统启动时自动检测 NEW_COLUMNS 列表，对旧数据库执行 ALTER TABLE ADD COLUMN，无需手动迁移。当前数据库 schema 包含 33+ 字段。
